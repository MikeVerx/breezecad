# «Инструмент лёг — программа живёт»: архитектура изоляции

Вопрос был такой: может, перестроить инструменты так, чтобы они работали на
отдельном слое и падение инструмента не роняло программу. Ответ: **да, и делать
это стоит по ступеням** — первые две дают 90 % пользы за малую цену, третья —
полная изоляция, но это заметная переделка.

## Откуда вообще берутся вылеты

| Источник | Что это | Как ловится сейчас | Как ловить |
|---|---|---|---|
| Исключения C++ в нашем коде | `json::type_error`, `filesystem_error`, `bad_alloc`… | никак (B-06) | Ступень 1 |
| Исключения OCCT (`Standard_Failure`) | ядро отказалось строить | ловятся внутри операции — хорошо | уже есть |
| Аппаратные сбои внутри OCCT | плохой адрес, деление на ноль | `FaultGuard`, но с «миной» (B-07) и не во всех потоках (B-08) | Ступень 2, затем 3 |
| Зависания | вечный цикл, минутная булева операция | никак (B-03, B-09) | Ступени 2–3 |
| Переполнение стека | глубокая рекурсия | никак (B-10) | ограничение глубины + Ступень 3 |
| Модули сторонних авторов | что угодно | маркер «упал в прошлый раз» — хорошо | Ступень 3 для модулей |

## Ступень 1 — страховочная сетка кадра (1–2 дня)

Один `try/catch` вокруг тела кадра в `Application::Run`, и отдельные — вокруг
обработчика каждого инструмента/панели (`SketchEditor::Update`, `OperationEditor::DrawPanel`,
команды из `ActionRegistry`).

Что делать при пойманном исключении:
1. Записать в лог тип, текст и последнее действие (`mon::LastAction()` уже есть).
2. **Аварийное автосохранение** всех изменённых документов в папку автосохранений
   (уже есть механизм `Autosave`, нужен метод «сохранить сейчас»).
3. Сбросить «упавший» инструмент: открытая операция → `Cancel`, инструмент
   эскиза → `Reset()`. Документ при этом остаётся как был до инструмента
   (предпросмотр живёт в документе — `Cancel` его уберёт).
4. Красная плашка: «Инструмент „Скругление“ дал сбой и был закрыт. Работа
   сохранена в автосохранение. Сообщите, пожалуйста: [Открыть лог]».

**Важно:** ImGui после исключения посреди кадра оказывается с незакрытыми
`Begin/End`. В нашей версии Dear ImGui (1.91.9b) для этого есть штатная пара:
`ImGui::ErrorRecoveryStoreState()` в начале обработчика инструмента и
`ImGui::ErrorRecoveryTryToRecoverState()` в `catch` — иначе ImGui сам упадёт
на проверке в следующем кадре.

Цена: ~150 строк. Закрывает класс B-01/B-04/B-11/B-12 даже до их точечного
исправления.

## Ступень 2 — честная защита ядра (2–4 дня)

1. Заменить `FaultGuard` на родной механизм OCCT: `OSD::SetSignal(false)` один
   раз при старте и `OCC_CATCH_SIGNALS` в начале каждого `try` вокруг операции.
   Сбой (в том числе в рабочих потоках булевых операций) превращается в
   `Standard_Failure` с правильной раскруткой стека — без «мины» (B-07, B-08, B-22).
   - Нужно проверить на Windows (MinGW): OCCT ставит свой
     `SetUnhandledExceptionFilter`, наш в `main.cpp` должен ставиться **после** и
     передавать управление дальше.
2. **Отмена и предел времени** для перестроения: флаг отмены + `Message_ProgressRange`
   в долгих вызовах OCCT. Предел, например, 60 с на операцию → операция
   получает ошибку «Слишком долго — упростите геометрию», программа живёт (B-09).
3. После любого перехваченного аппаратного сбоя — плашка «Ядро сбоило,
   рекомендуется сохранить и перезапустить» (память OCCT могла пострадать).

## Ступень 3 — геометрия в отдельном процессе (2–4 недели)

Это и есть «отдельный слой» в полном смысле. Окно (интерфейс, документ,
отмена, файлы) — один процесс. Ядро (OCCT: перестроение, сетка, экспорт) —
второй процесс, «работник».

```
 +-----------------------+        команды         +------------------------+
 |   breezecad.exe       |  -------------------> |  breezecad-kernel.exe  |
 |   окно, документ,     |   документ (JSON),     |  OCCT, перестроение,   |
 |   отмена, файлы       |   «перестрой с N»      |  сетка, STEP/STL       |
 |                       | <------------------- |                        |
 |   показывает сетку    |   треугольники,        |  упал/завис?           |
 |                       |   статусы операций     |  -> окно перезапускает |
 +-----------------------+                        +------------------------+
```

- Упал работник → окно перезапускает его, перестраивает с начала, а операция,
  на которой он упал, получает ошибку «Ядро не смогло выполнить». Документ и
  отмена не страдают вообще.
- Завис работник → окно снимает его по таймеру. Никаких вечных ожиданий.
- Бонус: работнику можно ставить свой предел памяти — на 8 ГБ ноутбуке
  геометрия не съест память окна.

**Цена и сложности:**
- Окну сейчас нужны сами фигуры OCCT (`TopoDS_Shape`) для выбора граней и рёбер
  мышью (`Viewport::Pick`, `FaceReference`). При разделении окно получает
  только сетку + «какой треугольник какой грани»; выбор, проекция рёбер в
  эскиз, измерения — запросами к работнику. Это основная работа.
- Передача: общая память или канал. Сетка средней детали — единицы МБ, это
  миллисекунды.
- Модули сторонних авторов — туда же, в свой процесс, тогда их падение тоже не
  трогает окно.

**Когда:** после первой стабильной альфы. До этого Ступени 1–2 дают почти тот же
результат для пользователя.

## Что уже сделано хорошо и стоит сохранить

- Ошибка операции не роняет перестроение: тела откатываются к «до операции»,
  операция получает статус с текстом (`Model.cpp:808-944`).
- Фоновое перестроение работает на **копии** документа и фигур — гонок нет.
- Модули: маркер «модуль был запущен» на диске и отключение упавшего модуля при
  следующем запуске — правильная идея, её стоит расширить на всё приложение
  («последнее действие перед вылетом» уже пишется монитором).
- Автосохранение с ротацией трёх копий.

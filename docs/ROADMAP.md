## Фаза 1.5 — Рефакторинг

**Статус:** 🔜 СЛЕДУЮЩАЯ

**Цель:** код приятный для чужого программиста.

### Задачи

1. **Разбить `Application.cpp`** (4700 строк) на модули:
   - `ui/ribbon/` — вкладки, группы, кнопки.
   - `ui/panels/` — левая панель, правая навигация.
   - `ui/dialogs/` — настройки, о программе.
   - `app/` — Application, CommandStack.
   - `doc/` — BreezeDocument, DocumentData.
   - `kernel/` — IKernel, OcctKernel.

2. **Слои** — `platform / kernel / doc / app / ui`.
   UI не знает про OCCT. Ядро не знает про ImGui.

3. **clang-format** — единый стиль.

4. **README.md** — описание архитектуры, как собрать, как помочь.

5. **CONTRIBUTING.md** — как делать PR.

6. **Тесты** для ядра (базовые) — Catch2 или doctest.

7. **Закрыть UI_ISSUES** — все визуальные баги.

### Критерий готовности

Опытный C++-разработчик открывает репо — понимает за 5 минут.
Не морщится. Может собрать и запустить без чтения чатов.

## Фаза 1.6 — Кастомный title bar (Windows-only)

**Статус:** ⏸ запланирована

**Цель:** QAT становится титульной строкой окна. Слева — кнопки QAT,
по центру — имя проекта, справа — кнопки окна `[—] [□] [×]`.

**Скрин из Inventor / КОМПАС:** так у всех взрослых CAD.

### Задачи

1. `glfwWindowHint(GLFW_DECORATED, GLFW_FALSE)` под `#ifdef _WIN32`.
2. Рисуем верхний ряд в ImGui (QAT + название + кнопки окна).
3. Перетаскивание окна за QAT.
4. Кнопки Свернуть / Развернуть / Закрыть.
5. Ресайз окна за края (8 зон).
6. Двойной клик по QAT = maximize/restore.
7. **Windows Snap** через WinAPI `WM_NCHITTEST` + `DwmExtendFrameIntoClientArea`.

### Риски

- Snap теряется — вернуть через хук.
- Кроссплатформенность — под `#ifdef`.
- Требует день-два.

## Фаза 2 — Функционал детали

**Статус:** ⏸ запланирована

**Цель:** довести деталь до рабочего состояния.

### Что делаем

1. **Плавающие окна операций:**
   - Выдавливание (направление, расстояние, конус, имя тела).
   - Вращение (ось, угол, конус).
   - Отверстие (тип, резьба, крепёж, ограничение).
   - Сопряжение (постоянный радиус / переменный / угловой / грань / полное).
   - Оболочка (внутрь/наружу, толщина, удаляемые грани).
   - Фаска (расстояние, угол).

2. **Инлайн-виджет вьюпорта** — поле ввода рядом с геометрией.

3. **Левая панель — вкладки:**
   - Дерево.
   - Параметры (свойства выделенного).
   - Переменные (fx).

4. **ViewCube с рёбрами** — 12 рёбер + 8 углов кликабельны.

5. **Toast-уведомления** — «Файл сохранён», «Ошибка экспорта».

6. **Таймлайн операций** — горизонтальная лента под вьюпортом.

7. **Эскиз — базовые операции:**
   - Прямоугольник, Окружность, Дуга, Многоугольник, Точка, Текст.
   - Смещение, Копировать, Поворот.

## Фаза 3 — Свой формат .bzc

**Статус:** ⏸

**Цель:** отказаться от OCAF как основного формата.

### Что делаем

1. Реализовать **`DocumentData`** — независимая от ядра структура.
2. **`history.bin`** — параметрическая история.
3. **`geometry.brep`** — кэш B-rep.
4. **`tessellation.bin`** — кэш триангуляции.
5. **`manifest.json`** — версия, метаданные.
6. **Миграции** — v1.0 -> v1.1 -> ...
7. **OCAF** — перевести в модуль (мост для `.cbf`).
8. **Atomic write** для автосохранений.
9. **3 версии автосохранений** + диалог восстановления после краша.

### Критерий готовности

- Файлы `.bzc` открываются в новых версиях без пересчёта.
- `.cbf` (OCAF) читается через модуль.

## Фаза 5 — Модули + плагины

**Статус:** ⏸

**Триггер:** ядро стабильно, `.bzc` работает, 3-5 модулей от нас.

### Что делаем

1. **Система модулей** — установка / удаление / обновление.
2. **Manifest модуля** — зависимости, требования к железу.
3. **Проверка железа** при установке (min_gpu_ram_mb, min_ram_mb).
4. **Модуль «Черчение»** — отдельная разработка.
5. **Модуль «OCAF-мост»** — для `.cbf`.
6. **Плагинная система:**
   - C-ABI для C++ плагинов.
   - Lua для скриптов.
   - JSON для UI-тем.
7. **Процесс-менеджер плагинов** — отключение крашащих.
8. **Диалог при краше:** скопировать отчёт / отключить плагин / восстановить.

## Фаза 7 — STL Viewer + диагностика

**Статус:** ⏸

### STL Viewer (отдельный workspace)

**Только измерения:**
- Расстояние между точками / плоскостями.
- Угол между гранями.
- Диаметр цилиндрических поверхностей.
- МЦХ (объём, центр тяжести).

**Нельзя:** редактировать геометрию, строить поверх, конвертировать в деталь.

### Диагностика в 3D-модели

- Информация об объекте.
- Расстояние и угол.
- МЦХ (масса, объём, центр тяжести).

## Фаза 8 — Оптимизация под слабое железо

**Статус:** ⏸

**Цель:** стабильная работа на i3-4170 / 8 ГБ DDR3 / iGPU.

### Что делаем

1. **Асинхронная триангуляция** — UI не блокируется.
2. **LOD (Level of Detail)** — упрощение геометрии для дальнего плана.
3. **Виртуализация дерева** — >500 узлов рендерим окно в 100.
4. **Ленивая загрузка кэшей.**
5. **Оптимизация шейдеров** — минимум переключений.
6. **Проверка на GWNR51416-BL** (Ryzen 5 + Vega 8).
7. **Замеры:** старт, FPS, RAM, отклик на операции.

### Бюджет

- Старт: <1 сек.
- Деталь (100 фич): RAM <100 МБ.
- Сборка (200 деталей): RAM <500 МБ.
- FPS в 3D: 60 без нагрузки, ≥30 с деталью 1000 фич.

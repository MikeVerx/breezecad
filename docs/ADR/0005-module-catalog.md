# ADR-0005: Каталог модулей вне магазинов приложений

- **Status:** Proposed
- **Date:** 2026-10-15

## Context

Модули ставятся пакетами `.bzmod` (`ModuleManager::Install`, «Настройки →
Модули»); CI собирает их под каждую систему и архитектуру
(`bz-<id>-<version>-<system>-<arch>.bzmod`) и кладёт на страницу релиза
`modules`. Пользовательских модулей пока ставить неоткуда, кроме как скачать
файл вручную.

Требование автора: универсальный сайт / приложение, через который
пользователи ставят **свои и чужие модули**, ничего не запрашивая у магазинов
приложений, — на всех платформах, включая мобильные (ADR-0004).

## Decision

### Каталог

1. **Индекс каталога** — один JSON (`catalog.json`): id, название, автор,
   описание, версии, для каждой версии — пакеты по `<system>-<arch>`, хеш
   SHA-256, подпись, минимальная версия BreezeCAD, требования к железу из
   `module.json`. Хостинг на старте — GitHub (отдельный репозиторий каталога
   или Pages), без своего сервера.
2. **Публикация** — автор модуля присылает PR в репозиторий каталога (ссылка
   на релиз со своими `.bzmod` + запись в индекс); CI каталога проверяет
   хеши, подпись и что пакет открывается `ModuleManager`. Официальные модули
   попадают туда же из CI основного репозитория.
3. **Сайт** — статическая страница по индексу: поиск, карточки, скриншоты,
   кнопка «Установить», которая открывает ссылку
   `breezecad://install?module=<id>&version=<v>` (регистрируется
   установщиком на десктопе и манифестом на Android) или скачивает `.bzmod`.
4. **Внутри программы** — вкладка «Каталог» на странице «Настройки → Модули»:
   тот же индекс, установка и обновление в один тап через существующий
   `Install`. Отдельное приложение не нужно — каталог встроен.
5. **Доверие:** пакеты подписываются ключом автора (ed25519); программа
   проверяет хеш и подпись, показывает автора и «проверен / не проверен».
   Модуль без подписи ставится только с явным предупреждением. Защита от
   падений модулей — существующая (`modules`).

### Ограничения магазинов (честно)

- **APK с GitHub, RuStore, десктоп** — каталог работает полностью, включая
  нативные модули (`.so` / `.dll` / `.dylib`).
- **Google Play** запрещает приложению скачивать исполняемый код (`.so`,
  `.dex`) не через Play. Отдельное «приложение-установщик» это не обходит:
  загружать код всё равно будет сам BreezeCAD. В сборке для Play:
  - нативные модули — только встроенные в сборку;
  - каталог показывает **модули-данные**: шаблоны, библиотеки стандартных
    изделий, наборы команд на JSON (`app/scripting`, ADR-0002) —
    это не исполняемый код. Перед публикацией свериться с актуальной
    политикой Play;
  - ссылка «полная версия с любыми модулями» ведёт на APK с GitHub.
- **App Store** — загружаемый нативный код запрещён полностью; то же
  разделение, что для Play, но строже. Вопрос далёкого будущего.

### Следствие для формата модуля

В `module.json` добавить поле вида модуля: `native` (библиотека) или `data`
(только данные и JSON-команды). Каталог фильтрует по нему в сборках для
магазинов.

## Consequences

- Плюс: своего сервера не нужно; всё на GitHub, как и сборки.
- Плюс: модули-данные работают везде, включая магазины; это подталкивает
  авторов делать простые модули без нативного кода.
- Минус: в сборках для магазинов часть модулей недоступна — нужно ясно
  показывать это в каталоге, а не прятать.
- Минус: подпись и модерация PR в каталог — ручная работа автора проекта.

## Alternatives

- **Отдельное приложение-установщик** — отвергнуто: не обходит правила
  магазинов и дублирует страницу «Модули».
- **Свой сервер каталога** — отложено: GitHub хватает на старте.
- **Только ручная установка файлом** — остаётся как запасной путь, но для
  телефона неудобна.

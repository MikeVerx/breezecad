# ADR-0003: Окно сбоя и зависания — отдельный процесс

- **Status:** Proposed
- **Date:** 2026-10-14

## Context

При аварийной остановке программа просто исчезала, при зависании — серела.
Пользователь не понимал, что случилось, и ему нечего было переслать разработчику.
Первый тикет стороннего тестера (Arch + Hyprland) это показал: «прога умирает» —
а в логе был штатный выход, и разобраться удалось только по видео и архиву беты.

Требование автора: при сбое или критическом зависании — окно, которое объясняет,
что произошло, и даёт скопировать код ошибки. Обязательная часть основной ветки,
во всех сборках, не только в бете.

## Decision

1. **Окно — отдельный процесс той же программы**: `breezecad --crash-window <отчёт>`
   и `breezecad --hang-window <pid> <отчёт> <секунды>` (`src/app/shell/CrashWindow`).
   Упавший процесс не может рисовать (куча и OpenGL в неизвестном состоянии),
   зависший — тоже (его главный поток стоит).
2. **Сбой.** Обработчики сигналов (Linux, macOS) и исключений (Windows) в `main.cpp`
   пишут текстовый отчёт и запускают окно (`app::crash::ShowCrashWindow`).
   Всё, что нужно обработчику, готовится заранее (`crash::Prepare`): пути, командная
   строка; в обработчике на Linux/macOS — только `write`, `fork`, `execv`.
   На Windows своё окно заменяет системное «Программа не работает».
3. **Зависание.** Поток-сторож (`crash::StartHangGuard`) следит за `mon::Beat` главного
   цикла. 15 с без удара — пишет отчёт и показывает окно «не отвечает»: «Подождать»
   или «Закрыть BreezeCAD». Если цикл ожил — сторож закрывает окно сам. Нативные
   диалоги (`mon::Waiting`) и сон компьютера зависанием не считаются.
4. **Код ошибки** — `BZ-<вид>-<6 hex>` (`core/CrashCode`): хеш стека без того, что
   меняется от запуска к запуску (адреса ASLR, папка установки). Один сбой в одном
   месте одной сборки — один код; по коду из чата видно, одна это ошибка или разные.
5. **Отчёт никуда не уходит сам** (ноль телеметрии): окно предлагает скопировать
   код, скопировать отчёт целиком (с описанием компьютера) или открыть его папку.
   Бета хранит отчёт в папке сеанса (`crash.txt`, `hang.txt` — попадают в zip);
   остальные сборки — в `<папка настроек>/reports`, последние 20.

## Consequences

- Пользователь видит, что случилось, и может отправить код одной строкой.
- Перезапуск из окна: работа восстанавливается из автосохранения, как и раньше.
- Поток-сторож работает всегда: четыре проверки в секунду, без выделений памяти
  в обычном режиме.
- На Linux копирование работает, пока окно открыто (буфер обмена X11 живёт с
  владельцем); поэтому есть и «Открыть папку с отчётом».
- Порог зависания — 15 с; `BZ_HANG_SECONDS` меняет его (для проверки окна).

## Alternatives

- **Окно из самого упавшего процесса** (MessageBox в фильтре исключений): на Windows
  возможно, на Linux нет ни одного безопасного способа нарисовать окно из обработчика
  сигнала; разное поведение на трёх системах.
- **Только отчёт при следующем запуске** (как в бете): пользователь не понимает, что
  случилось сейчас, а обычные сборки его вовсе не видят.
- **Отправка отчёта на сервер** — противоречит принципу «ноль телеметрии без согласия».

# Промт: Рефакторинг монолита

**Когда использовать:** Фаза 1.5 — разбить `Application.cpp` (4700 строк)
на модули. Копируется как задача для ассистента.

---

## Текст промта

Задача: **рефакторинг `src/app/Application.cpp`** (4700+ строк) на модули.

Целевая структура — в `docs/ARCHITECTURE.md`, раздел 12.

### Слои (правило)

    ui/        ImGui, ribbon, панели, диалоги
    app/       Application, CommandStack
    doc/       BreezeDocument, DocumentData
    kernel/    IKernel, OcctKernel
    platform/  GlfwWindow, FileDialog

**UI не знает про OCCT. Ядро не знает про ImGui.**

### Шаги рефакторинга

**Шаг 1. Инвентаризация**
- Найти все методы класса `Application`.
- Сгруппировать по назначению:
  - QAT, ribbon, вкладки → `ui/ribbon/`
  - Дерево, панели → `ui/panels/`
  - Диалоги → `ui/dialogs/`
  - Home Screen → `ui/HomeScreen.cpp`
  - ViewCube → `ui/ViewCube.cpp`
  - Состояние + команды → `app/Application.cpp`
  - Работа с документом → `doc/`

**Шаг 2. Вынести одно подсистему**
- Начать с **самой независимой** — например, `ui/dialogs/`.
- Проверить сборку после каждого шага.
- НЕ выносить всё сразу.

**Шаг 3. Переделать интерфейсы**
- Между UI и документом — интерфейс.
- Между документом и ядром — `IKernel`.

**Шаг 4. Тесты для ядра**
- Catch2 или doctest.
- Базовые: extrude, boolean, fillet.

**Шаг 5. Привести к clang-format**
- Файл `.clang-format` в корне.
- `clang-format -i src/**/*.cpp src/**/*.h`

**Шаг 6. README + CONTRIBUTING**
- Как собрать.
- Как устроен проект.
- Как помочь.

### Правила

1. **Коммит после каждой вынесенной подсистемы.**
2. **Проверка сборки + запуск после каждого шага.**
3. **Если упало — откат, не докручивание.**
4. **Ни один файл не >500 строк.**
5. **Member-переменные вместо static.**
6. **Не менять поведение** — только перенос кода.

### Критерий готовности

- В `src/` структура из ARCHITECTURE.
- `Application.cpp` < 500 строк.
- Сборка чистая.
- Приложение работает как раньше.
- Чужой программист понимает за 5 минут.

### Риски

- **Потеря работоспособности** — откат на `git checkout`.
- **Долгая сборка** — модульность ускорит.
- **Забытые зависимости** — компилятор подскажет.

### Стратегия

Разбивать **по одной подсистеме в коммит**. Не пытаться сделать всё
за один заход. Каждый шаг — рабочий билд.

## Промты для конкретных шагов

**Начать инвентаризацию:**

> Проведи инвентаризацию методов `Application.cpp`. Сгруппируй по
> назначению (QAT, ribbon, диалоги, дерево, документ, ядро). Покажи
> таблицу: метод → целевой файл. Никаких правок пока.

**Вынести первую подсистему:**

> Выносим `ui/dialogs/` в отдельный модуль. Покажи план: какие методы,
> какие зависимости, какой файл создаём. Потом патч. После — сборка.

**Финальная проверка:**

> Проверь: `Application.cpp` < 500 строк? Все слои соблюдены? Сборка
> чистая? clang-format применён? README и CONTRIBUTING на месте?

# Промт: Миграция в новый чат

**Когда использовать:** при переполнении контекста или переходе на другой
ассистент. Копируется как **первое сообщение** в новый чат.

---

## Текст промта

Привет! Мы продолжаем работу над BreezeCAD.

Прочитай, пожалуйста, эти файлы из репозитория (по порядку):

1. `docs/HANDOFF.md` — инструкция для тебя.
2. `docs/RULES.md` — 38 правил работы.
3. `docs/PROJECT_STATE.md` — где мы сейчас.
4. `docs/CANON_FEATURES.md` — канон функционала.
5. `docs/ROADMAP.md` — план по фазам.
6. `docs/TECH_DEBT.md` — открытые баги.
7. `docs/UI_ISSUES.md` — визуальные баги.

Репо публичный: https://github.com/MikeVerx/breezecad

Если ссылки недоступны — скажи, я скину содержимое каждого файла
отдельным сообщением.

**Текущая задача:** [ОПИСАНИЕ — что делаем сегодня]

После прочтения:
1. Кратко подтверди: кто я, что за проект, где мы, какие правила.
2. Задай 1-2 уточняющих вопроса, если что-то неясно.
3. Не начинай работу без моей отмашки.

## Что скинуть дополнительно (если нужно)

- Последние коммиты: `git log --oneline -10`
- Структура: `ls -R src/`
- Открытые вопросы в UI_ISSUES / TECH_DEBT

---

## Если ассистент не может читать GitHub

Скинь ему содержимое этих файлов отдельными сообщениями (в порядке
из списка выше). Не всё сразу — по одному, чтобы не потерялось.

---

## Что делать после подтверждения

1. Проверить HANDOFF «Контрольные вопросы» — ассистент должен ответить.
2. Открыть нужный файл кода.
3. Сверить задачу с CANON_FEATURES.
4. Предложить план (что, зачем, риск, время).
5. Действовать по RULES.

---

## Чего НЕ делать

- Не начинать работу без отмашки.
- Не гадать — спрашивать.
- Не менять UI без сверки с CANON_FEATURES.
- Не использовать sed -i.
- Не предлагать ребут.

## 1. Правки файлов

### Что РАБОТАЕТ

**Python heredoc:**

    python << 'PYEOF'
    import re
    path = 'src/app/Application.cpp'
    with open(path, 'r', encoding='utf-8', newline='') as f:
        content = f.read()
    # ... правки ...
    with open(path, 'w', encoding='utf-8', newline='') as f:
        f.write(content)
    PYEOF

Ключевое:
- `encoding='utf-8'` — кириллица.
- `newline=''` — сохраняет CRLF.
- `<< 'PYEOF'` — кавычки вокруг маркера, чтобы shell не подставлял переменные.

**Замена функции целиком через границы:**

    start_marker = 'void Application::DrawX() {'
    idx = content.find(start_marker)
    next_fn = content.find('\nvoid Application::', idx + len(start_marker))
    content = content[:idx] + new_body + content[next_fn+1:]

Надёжнее regex — не рвётся на больших функциях со скобками внутри.

**Замена по номерам строк** (когда знаем точные границы):

    with open(path) as f:
        lines = f.readlines()
    start = 1762 - 1
    end   = 1844 - 1
    new_lines = lines[:start] + [new_block] + lines[end:]
    with open(path, 'w') as f:
        f.writelines(new_lines)

**Regex только для простых случаев** — `re.subn(pattern, lambda m: replacement, content)` с lambda, чтобы не парсились escape-последовательности в replacement.

### Что НЕ РАБОТАЕТ

**sed -i** — ломает CRLF. Переписывает файл Unix-переводами, git показывает весь файл как изменённый (1000+ строк diff вместо 20).

**Прямой regex по большим функциям** — `re.subn(r'void Application::X\(\) \{.*?\n\}', ...)` — не находит из-за вложенных скобок.

**`python -c "..."` с кириллицей** — падает с «bytes can only contain ASCII». Только heredoc.

**`..` в UI** — шрифт Inter не содержит многоточия в кириллических глифах, рендерится как `?`. Вместо обрезки — уменьшать шрифт, потом сокращать подпись.

**Box-drawing в heredoc** — `┌─┬─┐` теряются при вставке в терминал. Только ASCII (`+`, `-`, `|`).

**Длинные ответы с вложенными ```cpp/```json** — при копировании ломаются, часть теряется. Решение: короткие команды, до 250 строк, без вложенных блоков.

## 2. Проверка и отладка

### Работает

**Проверка после правки:**

    grep -a -n "что_искали" файл
    diff file.bak file
    head -20 file
    wc -l file
    file file           # line endings

**`grep` всегда с `-a`** — иначе кириллица считается бинарной, вывода нет.

**TRACE-инструментация:**

    BREEZECAD_TRACE=1 ./breezecad.exe
    # лог в breezecad_trace.log

**Размер diff** — если >200 строк для точечной правки, скорее всего сломаны line endings. Проверить `file` до и после.

**RAM через WinAPI** (`GetProcessMemoryInfo`) — `OSD_MemInfo` в OCCT под MinGW вызывает `wmic`, которого нет в Windows 11 24H2+.

**objdump для DLL:**

    LC_ALL=C objdump -p exe | tr -d '\0' | grep -aE 'DLL Name:' | awk '{print $3}'

### Не работает

**`xxd`** — не установлен в MSYS2. Использовать `od -c` или `hexdump -C`.

**`fetch` в HTML с `file://`** — не грузит SVG. Решение: встраивать SVG inline прямо в HTML.

## 3. Сборка

### Работает

    cd ~/BreezeCAD/build && ninja 2>&1 | tail -20
    cd ~/BreezeCAD && ./run.sh

**Ошибки иконок:** `ICON_FOO` не объявлена → проверить `IconsFontAwesome.h`. Опечатка или иконка не добавлена.

**`not declared in this scope; did you mean 'X'?`** — компилятор сам подсказывает похожее имя. Быстро исправляется.

### Не работает

**Патч по regex поверх большого файла** — если в replacement-строке есть `\B`, `\W` и т.п., Python падает с `bad escape`. Только lambda или ручная замена через `.replace()`.

## 4. Дизайн и UI

### Работает

**Иконки в стиле Lucide:**
- viewBox 24x24.
- stroke-width 2.
- stroke-linecap round, stroke-linejoin round.
- fill none, текущий цвет через `currentColor`.
- Для тонирования под тему: `fill="currentColor" opacity="0.35"` для полупрозрачных элементов.

**Превью иконок через HTML:** встраивать SVG inline (не через fetch) — работает с `file://`.

**Стрелка внутри кнопки** (вертикальная полоса справа) — выравнивает высоты групп, не ломает компоновку.

**RibbonGroupEnd с member-переменной** — `myRibbonGroupStartY` в классе, не `static` локально. Иначе Start и End используют разные переменные, TARGET_H не работает.

### Не работает

**Адаптивный iconSize** — иконка «прыгает» в зависимости от текста, выглядит неравномерно. Фиксированный размер для big (32) и small (22-24) — предсказуемее.

**Обрезка текста с «..»** — рендерится как `?`. Только уменьшение шрифта или сокращение подписи.

## 5. Git

### Работает

    git add docs/X.md src/Y.cpp
    git commit -m "тип(область): краткое" -m "детали"
    git push

**Типы коммитов:** feat, fix, refactor, docs, build, chore, assets, wip.

**Если push упал** — не переписывать историю, а `git pull --rebase`, потом push.

**Backup перед правкой важных файлов:**

    cp file file.bak
    # ... правки ...
    rm -f file.bak    # если всё ок
    # или
    mv file.bak file  # откат

**Не удалять .bak сразу** — оставлять до первого успешного запуска.

### Не работает

**Многострочный `-m` без второго `-m`** — git ломает по кавычкам. Только два `-m`: краткое + подробное.

## 6. Работа с OCCT

### Работает

- `BRepBuilderAPI_MakeVertex`, `MakeEdge`, `MakeFace` — простые примитивы.
- `BRepTools::Write()` / `Read()` — B-rep.
- `StlAPI_Writer`, `STEPControl_Writer` — экспорт.
- `BRepGProp::VolumeProperties` — МЦХ (масса, объём, центр тяжести).

### Не работает / устарело

**`Standard_True/False/Real`** — deprecated в OCCT 7.7+. Использовать `true/false/double`. Warning, не ошибка, но лучше не копипастить.

**`OSD_MemInfo`** — вызывает `wmic`, удалён из Windows 11 24H2+. Заменено на `GetProcessMemoryInfo`.

## 7. Работа с ассистентом

### Что работает в связке

- **Короткие команды** (одно облачко, до 250 строк) — копипаст без потерь.
- **Проверка после каждой правки** — пользователь видит результат, не гадает.
- **Скрин после запуска** — единственный способ проверить визуал.
- **Итерации по 5-10 правок**, потом коммит.
- **Отдельный бэкап перед рискованными правками** — быстро откатить.

### Что НЕ работает

- **Длинные ответы с вложенными ```код```** — ломаются при копировании.
- **Обрезка символов через `..`** — рендерится как `?`.
- **`static` для состояния между вызовами в членах класса** — лучше member-поля.
- **Адаптивные размеры в UI** — предсказуемость важнее.

### Философия

- Топология — святое. Кнопки не обрезаются, иконки не мелкие.
- Если сборка упала — откат, не «докручивание».
- Ошибки признавать честно («моя вина»), не защищаться.
- Спрашивать, если непонятно. 3 вопроса лучше 30 минут работы не в ту сторону.

## 8. Паттерны, которые прижились

1. **Три уровня тултипов** — название / краткое / подробное с задержками 0.5 / +1 / +1.5 сек.
2. **Atomic write для автосохранений** — .tmp + rename.
3. **LRU-кэш** для тяжёлых результатов операций.
4. **Member-переменные вместо static** в классах.
5. **SVG с currentColor** для тонирования под тему.
6. **Одна команда — одно облачко.** Проверка после.
7. **Backup до, проверка после, откат при падении.**

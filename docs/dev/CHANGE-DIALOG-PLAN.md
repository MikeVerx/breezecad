# План: окно «Изменение затрагивает другие детали» (ADR-0009, часть 2)

Рабочий план для отдельного чата. Решения автора — в
`docs/ADR/0009-assembly-change-dialog.md`, макет — в
`docs/dev/mockups/change-dialog-*.png`. Опора уже есть:
`doc::SketchSource` у проекций, `kernel/occt/SketchSource.cpp`, слежение
в сборке — `kernel::AdaptContextProjections` (вызывается из
`app/AssemblyState.cpp`, около строки 300).

## Шаги

1. **Обнаружение (ядро, без UI).** В `kernel/ContextProjection.h` добавить
   функцию, которая для детали в сборке собирает затронутые эскизы, ничего
   не двигая: проекции (`contextProjections`, `adaptive`), у которых
   кривая-источник изменилась (форма или положение) с прошлого следования
   или пропала. Для этого запоминать в `ContextProjection` (только во время
   работы, в файл не писать) «отпечаток» источника на момент прошлого
   следования. Результат: деталь → список эскизов → затронутые кривые.
   Тест: короб вокруг прямоугольника, к эскизу прямоугольника добавлен
   выступ — короб в списке, эскиз и кривая названы. Скругление
   прямоугольника — короба в списке нет.
2. **Когда проверять.** После завершения правки детали (`ReturnToAssembly`,
   сохранение детали в сборке) — не на каждом кадре. Сейчас
   `AssemblyState` адаптирует сразу и молча: для изменений исходного
   эскиза вместо этого — очередь деталей под решение. Сдвиг компонента
   и изменения без смены источника по-прежнему адаптируются молча, как
   раньше.
3. **Варианты (ядро).**
   - *Игнорировать:* проекция затронутых кривых становится независимой
     (`adaptive = false`), геометрия детали не меняется.
   - *Автоадаптация:* текущее `AdaptContextProjections` по затронутым
     эскизам, после него — решатель. Ошибки эскиза
     (`analysis.failing`, `BrokenProjections`) — в превью.
   - *Мимикрирование с зазором:* затронутые кривые детали Б строятся
     заново эквидистантой нового контура источника на расстоянии зазора
     (`sketch/Offset.h`: `OffsetChain`), прежние зависимости переносятся
     на новые кривые, где совпадает тип кривой. Считать только затронутые
     цепочки, без перестроения всей сборки.
   - *Ручное:* очередь затронутых эскизов по порядку дерева. Открыть
     первый с `RestoreBeforeBreak`, если галочка «Откатить зависимости»
     включена. По выходу из эскиза — следующий; по завершении правки
     детали — снова шаг 2.
4. **Превью (рендер).** Отдельный маленький вид OCCT во вкладке окна,
   только для просмотра: вращение ЛКМ, масштаб колесом. Деталь — серым,
   источник — синим пунктиром (прозрачно); изменившиеся эскизы — красной
   (Игнорировать) или жёлтой (Авто) линией; ошибки — красными кружками
   «!»; изменившийся объём — красная полупрозрачная дымка, видная сквозь
   тело (разность объёмов до и после: `BRepAlgoAPI_Cut` в обе стороны,
   рисовать без теста глубины). Превью считать в фоне и кэшировать по
   варианту: переключение вариантов — мгновенно.
5. **Окно (UI).** По макету, тема из `ui/Theme.cpp`, строки через `Tr`
   (+ переводы). Модальное, без ✕: выбор обязателен; «Так же для всех» —
   применить и пройти остальные без окна. Подвал: «← Предыдущая», главная
   кнопка называет действие.
6. **Проверка.** doctest на шаги 1 и 3; UI-тест на Xvfb (сценарий
   `scripts/ui-test/scenario-change-dialog.sh`): сборка из двух деталей,
   правка эскиза первой → окно → каждый вариант → результат.

## Не забыть

- Отмена: решение в окне — одна запись истории сборки и деталей.
- Мобильная версия: то же окно во весь экран, превью сверху, варианты
  снизу (макет — отдельно, до кода).
- Производительность на эталонном слабом ноутбуке: обнаружение — без
  перестроения тел, только эскизы.

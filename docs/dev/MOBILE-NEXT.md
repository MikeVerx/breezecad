# Мобильная версия — что дальше и как работать (итог сессии 17.10.2026)

Читать после HANDOFF.md §1–2 и §6в. Это рабочая инструкция для следующего чата: открытые
ошибки, порядок работы, план редизайна. История — MOBILE-PORT.md («После четвёртой/пятой проверки»).

## Где мы

Первый по-настоящему рабочий прототип: на телефоне (OnePlus Nord CE5) можно начать и
нарисовать деталь — эскиз, размеры, выдавливание, вращение. 60–75 кадров/с в работе.
Автор: «минимально работоспособно, хоть и коряво». Главная беда — **кнопкам и функциям не
хватает места**, интерфейс держится на костылях. Нужен **масштабный редизайн управления**
(см. ниже), но шагами: продумать → макет → «да» автора → код → проверка тапом.

Последняя сборка: ветка `feat/android-full` (PR #38 в `next`, в `main` не сливаем),
APK — пре-релиз `android-build`. Снимок версии ещё не сохранён — если автор попросит:
ветка `preview/android-3` от текущего `feat/android-full` + ручной запуск `android.yml`.

## Правила работы (мои, после ошибок 17.10 — обязательно)

1. **Не писать «исправлено», пока не проверено настоящим тапом.** Тестовые команды
   эмулятора (`--es bz "…"`) открывают экраны в обход пальца и баги ввода не ловят
   (17.10 я отдал сборку, где «›» и нампад не работали, сославшись на такой снимок).
2. Каждый баг ввода с записи автора → **свой шаг в `scripts/android/smoke-apk.sh`**:
   `adb shell input tap/swipe` по координатам из лога приложения (`Touch: … at x,y` в dp,
   `dp()` переводит в пиксели) и проверка по строке лога (`Strip: open`, `Keyboard: typing/numpad on`).
   Шаг печатает `step <имя>: FAILED — …` и роняет джобу. Образец — шаги 13–14.
3. APK автору — только когда android-джоба зелёная **и** снимки нужных шагов посмотрены
   (они в `android-build` как `emulator-N-*.png`; выкладываются, только если прогон прошёл).
   Чего эмулятор проверить не может — прямо написать автору «не проверено, проверь вот это».
4. Запись экрана изучать **покадрово** (ffmpeg 1 кадр/с листами 3×4, спорные места 3–4 кадра/с
   и в полный размер), а не по первому впечатлению: что нажато, что ожидалось, что произошло.
5. Новые интерфейсы — сначала картинкой (`docs/dev/mockups/gen.py`, шрифты из `assets/fonts`),
   в код — только после «да» автора. Писать автору по-русски, в том числе по ходу работы.
6. Коммит = одна логическая часть, и **каждый коммит собирается сам** (17.10 коммит 242b905
   ссылался на изменение из следующего). What/Why/Where/Tested, по-русски.
7. Сборка в песочнице: `bash scripts/android/dev-setup.sh` (≈1 мин), затем
   `cmake --preset android-x86_64` и `ninja -C build/android-x86_64 <нужные .o>` — быстрая проверка
   компиляции изменённых файлов (полная сборка на 2 ядрах ~40 мин, не нужна). Десктоп/Windows — CI.
   Юнит-тесты без OCCT можно гонять хост-g++ (пример — DimensionArrangeTests, команда в MOBILE-PORT).
8. Ждать CI фоновой командой (`gh run view <id>` в цикле), итог — аннотация «APK on the emulator»:
   `gh api repos/MikeVerx/breezecad/check-runs/<job>/annotations`.

## Редизайн управления — с чего начать (автор, 17.10)

Цель автора: САПР на телефоне, удобный **как игра**; таких программ пока нет. Сейчас кнопкам
не хватает места, приходится делать костыли. Не латать дальше по одной кнопке, а продумать
систему. Порядок:
1. Сначала разговор и исследование, без кода: инвентаризация всех команд и состояний (модель,
   эскиз, операция, ввод значения, выбор), какие действия самые частые, что занимает место зря.
   Посмотреть, как решают игры (WoT Blitz, PUBG Mobile, Minecraft — их автор приводил) и мобильные
   редакторы: контекстные кольца/меню у пальца, панели по состоянию, жесты вместо кнопок.
2. Несколько концепций картинками (`gen.py`), каждая — со сценарием «нарисовать кронштейн
   от начала до конца»: сколько тапов, где палец, что закрыто.
3. Автор выбирает → поэтапный план → код шагами, каждый шаг — с проверкой тапом на эмуляторе.
Ошибки 1–10 выше чинить по ходу, если редизайн их не снимет.

## Найдено при прогоне 18.10 (вечер): код + Xvfb + готовая ПК-сборка

Как искал: чтение мобильного кода и правок 17–18.10; настольная сборка `feat/android-full` на Xvfb
(ПК-раскладка и `BZ_PHONE_LAYOUT=1` 915×412 и 640×320); ПК-сборка из `next-build` (16.10). Эмулятора
в песочнице нет (нет KVM). «Вживую» — воспроизведено на Xvfb; «по коду» — видно в коде, проверить.

**Порча документа и вылеты (первыми):**
24. Смена документа при открытой операции (вкладка на ПК, полоса проектов на телефоне, долгое
    нажатие «закрыть» на другом проекте) — **вживую**. Редакторы операций общие на программу, а
    `Workspace::Activate` операцию не закрывает; `FeatureOperationEditor::Edited` ищет id в новом
    документе (id у каждого документа свои, совпадают). (а) id не нашёлся — панель молча исчезает
    (`Reset`), фигура остаётся в старом документе вне истории; Ctrl+Z убирает эскиз под ней, операция
    остаётся с ошибкой. (б) id совпал с элементом другого типа — панель выдавливания правит «Эскиз2»
    (`static_cast<ExtrudeFeature&>` на эскиз: «? · вручную: 0»), «Готово» пишет шаг «Эскиз2». Это
    запись в чужую память — **главный кандидат на вылет №3** (пример + своя деталь в полосе).
    Править: при смене активного документа — Cancel открытой операции (или хранить Session* в редакторе).
25. Выделение и начатые щелчки эскиза общие для всех документов (`SketchEditor::mySelection`,
    `myClicks`, `myPicks`) — **вживую**: выделил линию в «Деталь2», перешёл в «Деталь1» (тоже эскиз) —
    подсвечена линия с тем же id, Delete удалил её в «Деталь1». Сбрасывать при смене документа.
26. Сохранение отменяет открытую операцию — **вживую** (ПК: ввёл 50 в выдавливании, «Сохранить» —
    панель закрылась, осталось 30, файл записан без правки). С ed1d001: `OperationEditors::Close` =
    Cancel, а его зовёт и `SaveDocument` (раньше Close применял). Так же сбрасывают вкладки левой
    рейки ПК и «Измерить». Сохранение должно применять (Done) или спрашивать.
27. Android 16 и «Назад» — по коду и документации Google. APK собирается с target SDK 36, причём он
    «плавает»: `package-apk.sh` берёт новейшую платформу на раннере. На Android 16 при target 36
    система не шлёт KEYCODE_BACK (predictive back по умолчанию): «Назад» = сразу выход, двойное
    «Назад» и Esc не работают. Эмулятор CI — Android 11, этого не видит. Править:
    `android:enableOnBackInvokedCallback="false"` (временно) или OnBackInvokedCallback; закрепить
    TARGET_SDK. Спросить автора, какой Android на Nord CE5.
28. Ложное «В прошлый раз BreezeCAD перестал отвечать» — по коду. Системное окно выбора файла

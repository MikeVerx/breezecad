# BreezeCAD `next` — журнал работы

Этот файл — точка входа для продолжения работы после перерыва или сброса
контекста. Читать сверху вниз: цель → решения → план → журнал → как продолжить.

## Цель

Собрать BreezeCAD «как он должен быть» в ветке `next`, с нуля по архитектуре,
но с переносом удачных решений старого кода. Автор (MikeVerx) проверяет готовую
сборку и даёт правки: «фиксить готовый билд быстрее, чем собирать по кускам».

Источник требований:
- `docs/PHILOSOPHY.md`, `docs/RULES.md` — философия и правила (обязательны).
- Документ вопросов/ответов (claude.ai, «BreezeCAD — вопросы перед разработкой»):
  ответы D1–D15 и «Решения и план на 9 вечеров». Ключевое перенесено ниже.
- Утверждённый макет интерфейса (claude.ai, дизайн-холст «BreezeCAD — концепт
  интерфейса»): светлая и тёмная темы, лента, левая панель, панель операции,
  вьюкуб как в Inventor. Логотип «B-поток» — `assets/brand/`.

## Ключевые требования (из ответов автора)

- Офлайн, без телеметрии. Отчёт о падении — только по согласию.
- Мышь как в КОМПАСе: зажатая ПКМ — вращение, зажатое колесо — сдвиг,
  прокрутка — масштаб, щелчок колесом — подтверждение операции, короткий
  щелчок ПКМ — контекстное меню. Центр вращения — точка модели под курсором,
  мимо модели — центр модели.
- Панель операции: Отмена / Применить / Готово, остаётся открытой.
- Эскиз: камера разворачивается к плоскости, F6 — вернуться к плоскости,
  Esc — выйти из инструмента/эскиза без потерь.
- Автосохранение: таймер 5 мин идёт только при несохранённых изменениях,
  запись в паузе 2–3 с, 3 копии, работает и в эскизе.
- Формат `.bzc`: ZIP + JSON, рецепт — источник правды, геометрия — кэш,
  неизвестные модули → частичное открытие. Старые файлы открываются всегда.
- Тема как в системе (светлая/тёмная), шрифт IBM Plex Sans, анимации с
  выключателем. Минимум окон, всё что можно — в левой панели.
- Стартовый экран; при первом запуске: «Проектов пока нет. Самое время творить!»
- OpenGL 3.3 минимум. Windows → macOS → (Android после 1.0) → Linux.
- Экспорт STEP AP214, STL, 3MF. Импорт STEP для просмотра и измерений.

## Архитектурные решения `next`

Подробно — в `docs/ADR/`. Кратко:

| Решение | ADR |
|---|---|
| Слои: core → sketch → document → kernel(OCCT) → render(OCCT) → ui(ImGui) → app | 0002 |
| Внутренние единицы: миллиметры и радианы; в файле единицы указаны явно | 0003 |
| Формат `.bzc` v1: ZIP (manifest.json + document.json) | 0004 |
| Сторонние библиотеки лежат в `third_party/` с закреплёнными версиями | 0005 |
| Отмена — командами со снимками изменённых объектов | 0006 |
| Вьюпорт OCCT рисует в свою текстуру (FBO), ImGui показывает её | 0007 |

UI не знает об OCCT, документ не знает ни об OCCT, ни об ImGui.

## План (вертикальный срез → расширение)

Статусы: [ ] не начато, [~] в работе, [x] готово.

1. [x] Каркас: ветка `next`, структура папок, CMake + presets, third_party,
   CI (Windows/macOS/Linux), README/ARCHITECTURE.
2. [x] core: ID, единицы, ошибки, журнал, выражения.
3. [x] sketch: модель эскиза, ограничения, решатель, тесты.
4. [x] document: документ, операции, параметры, команды/отмена, `.bzc`, тесты.
5. [x] kernel: построение тел из рецепта (эскиз → регионы → выдавливание,
   булевы), экспорт STEP/STL/3MF, тесты.
6. [x] render: вьюпорт OCCT в FBO, навигация как в КОМПАСе, подсветка, выбор.
7. [~] ui: тема и дизайн-система по макету, лента, левая панель (дерево,
   свойства, переменные), вкладки проектов, строка состояния, вьюкуб,
   стартовый экран.
8. [~] app: окно, цикл кадра, документы, инструменты эскиза, панель операции
   выдавливания, сохранение/открытие, автосохранение и восстановление.
9. [~] Проверка: сборка, тесты, скриншоты сценария
   «эскиз → размеры → выдавить → сохранить → открыть».
10. [ ] Дальше: вращение, отверстие, скругление, фаска; стили отображения,
    покраска граней; сборки; стандартные изделия.

## Как продолжить

1. `git switch next && git pull`.
2. Прочитать этот файл и последние ADR.
3. Взять первый пункт плана со статусом [~] или [ ].
4. Сборка в облаке: `cmake --preset linux-debug && cmake --build --preset linux-debug`,
   тесты: `ctest --preset linux-debug`.
5. После каждой рабочей порции: сборка → тесты → коммит → push → запись сюда.
6. Окружение облака после перезапуска контейнера (пакеты пропадают):
   `apt-get install -y libocct-*-dev libglfw3-dev libgl1-mesa-dev xvfb xdotool zenity gdb`
   (полный список — в истории WORKLOG за 2026-10-09). Проверка против OCCT
   8.0: `git clone --depth 1 -b V8_0_0 https://github.com/Open-Cascade-SAS/OCCT`,
   собрать все `*.hxx *.lxx *.gxx *.pxx *.h` в одну папку, Standard_Version.hxx
   из `adm/templates`, и прогнать команды из `ninja -t commands` с `-fsyntax-only`.
7. Интерфейс вживую: `scripts/ui-test/scenario-box.sh`, снимки в /tmp/shots.

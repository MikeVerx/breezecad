## Решения автора (кратко, по пунктам обсуждения)

| Тема | Решение |
|---|---|
| Ориентация | Телефон — всегда альбомная. Планшет — десктопная раскладка + масштаб; трёхрядные кнопки → два ряда крупнее |
| Какой вид открывать | По размеру окна в dp, не по соотношению сторон; ручной переключатель в настройках |
| Блок 1 | Дерево / Инструмент / Размеры (как КОМПАС) + ряд кнопок: от края экрана Выделение · Курсор · Отмена · ОК (ОК у рабочей области; у левши — зеркально). Бровка: лого (или на панели у камеры), сохранить, открыть, линейка |
| Блок 2 | Инструменты списком со скроллом и выпадашками. Бровка: fps + поиск. Борода: прогресс «74/100» |
| Блоки 3 и 5 | Островки над рабочей областью: вкладки (сворачиваются стрелкой) и «Отменить/Повторить» |
| Блок 4 | Полоса открытых проектов внизу рабочей области, без ползунка — листается свайпом вбок; стоит выше системной зоны жестов |
| Камера и углы | Вырез → панель на стороне камеры (слева или справа): лого + настраиваемый хотбар (текстуры, сечение…) выше и ниже выреза. Бровка блока 1 остаётся: сохранить, открыть, линейка. Без выреза лого в бровке, хотбара нет. Углы — отступ содержимого на радиус |
| Перестановка и размер | Блоки 1 и 2 меняются местами (левши); ширины настраиваются (20/60/20, «только иконки» 20/70/10); масштаб интерфейса с нижней границей ≈7 мм на кнопку |
| Системные жесты по краям | Не проблема: по бокам кнопки (тап/зажатие) и вертикальный скролл; проверить на живом телефоне свайп «наискось» у края |
| Курсор-капля | Круг под пальцем, кончик смещён и помечен; **следует за пальцем 1:1**; хитбокс кончика не выходит за рабочую область; протяжка продолжается над панелями. Эскиз — всегда включён; 3D — стартует выключенным |
| Точность | Лупа у кончика в эскизе + привязки (замедление убрано; вернуть галочкой, если не хватит) |
| Жесты | Курсор выкл: тап — выбор, 1 палец — вращение, 2 — сдвиг. Курсор вкл: 1 палец — курсор, 2 — вращение, **3 — сдвиг**. Щипок — зум. Тап 2 пальцами — отменить, 3 — повторить. Зажатие — контекстное меню с «Вставить». Качелька громкости — зум, выкл. по умолчанию |
| Видовой кубик | Свёрнутый — кнопка-значок; ориентацию показывает значок осей X/Y/Z слева внизу. Развёрнутый — крупный, вращение 1 пальцем, рёбра/вершины с увеличенной зоной, «Домой», сворачивается сам |
| Выделение | Кнопка режима; с курсором — двумя ОК по углам, без курсора — пальцем |
| Нампад | `0–9 . ( ) + − × / a b c d ⌫ ↑ ↓ ⌨ ↵`, 7×4; блок 1 при вводе расширяется до ≈300 dp; поле ввода видно всегда |
| «Завершить эскиз» | Закреплена над списком во **всех** версиях; цвет — мягкий акцент (не зелёный, не спорит с ОК) |
| Стилус | Прямой указатель без капли, наведение — привязки, кнопка пера — ПКМ/рамка, защита от ладони |
| Клавиатура/мышь | Сенсор по умолчанию, но физическая клава, мышь, тачпад работают |
| Репорты | Кнопка «Поделиться» (Intent) |
| Сбои и зависания | Отчёт пишется всегда; сторож в процессе `:crash` → уведомление → экран ошибки; при следующем запуске — причина прошлого выхода от системы + восстановление (ADR-0004) |
| Распространение | Сначала APK на GitHub, потом Google Play, App Store, другие |
| Модули | Каталог (сайт + вкладка «Каталог» в настройках). Play и App Store запрещают скачиваемый нативный код — там только модули-данные; полная версия — APK с GitHub (ADR-0005) |

## Стек и что мешает порту (по коду на 15.10.2026)

C++20 · Dear ImGui · OCCT · GLFW + OpenGL 3.3. Ядро переносится как есть.
Мешает: GLFW (18 файлов, в основном `src/platform`), прямые GL-вызовы и
`#version 330 core` (`Viewport`, `Icons`, `Splash`, `CrashWindow`,
`AppearanceEditor`), `pfd` в `FileDialogs`, `dlopen` модулей на Android/iOS.
`uiScale` (0 = автомат) в `Settings` уже есть — масштаб интерфейса готов.

## Шаг 1: ядро и тесты под Android (сделан)

- CI: `.github/workflows/android.yml` — **отдельно** от `build.yml`, не задерживает
  десктопные сборки и `next-build`. Матрица arm64-v8a / x86_64; x86_64 гоняет
  `bz_tests` на эмуляторе Android 11 (раннеры GitHub не исполняют arm64-код),
  итог тестов — аннотацией на странице прогона. Артефакт `bz-tests-android-arm64` —
  тесты для телефона: распаковать, включить отладку по USB, `bash run-tests.sh .`
- Выбор: NDK r27c (LTS), minSdk 28 (Android 9), `c++_shared` (OCCT — много .so),
  гибкий размер страниц (16 КБ). Пресеты `android-arm64`, `android-x86_64`
  (`BZ_BUILD_APP=OFF`; окружение: `ANDROID_NDK_HOME`, `BZ_ANDROID_DEPS`).
- Зависимости: `scripts/android/build-deps.sh` — FreeType 2.13.3 + OCCT 8.0.1,
  shared, ~1 ч на ABI; лежат в кэше Actions (ключ — версия NDK + хэш скрипта;
  кэш стирается после 7 дней без прогонов — тогда снова час).
- Тесты на устройстве читают данные из `/data/local/tmp/breezecad`
  (`tests/CMakeLists.txt`, `scripts/android/stage-tests.sh`, `run-tests.sh`).
  Выключен один тест — упаковка модуля через CMake (на устройстве CMake нет).
- Код ядра правок не потребовал. Проверка заранее: все исходники ядра и тестов
  прошли clang 18 + libc++ 18 (та же связка, что в NDK r27).
- Хвост на потом: `HostInfo::Detect` на Android говорит `os = "linux"` — модуль
  под Linux (glibc) посчитается совместимым. Решать вместе с каталогом модулей
  (ADR-0005): своё имя `android` + формат `.so` под bionic.

## Шаг 2: окно, OpenGL ES, 3D-вид, APK (сделан)

- Скачать на телефоне: https://github.com/MikeVerx/breezecad/releases/download/android-build/BreezeCAD-android.apk
  (пре-релиз `android-build`, обновляется каждым зелёным push в ветки android.yml;
  рядом — снимки с эмулятора `emulator-1-start.png`, `emulator-2-turned.png`).
- Приложение — `src/android/AndroidMain.cpp`, NativeActivity без Java: EGL + GLES 3,
  десктопный `render::Viewport` как есть (OCCT рисует в свой framebuffer, кадр
  копируется в окно `glBlitFramebuffer` — состояние GL, которое кэширует OCCT, не
  трогаем). Деталь-пример (`tests/data/кронштейн.bzc` → assets) строится в своём
  потоке. Жесты (курсор выкл.): 1 палец — вращение, 2 — сдвиг + щипок, двойное
  касание — показать всё. Рисует только по необходимости. Лог — logcat
  (тег `BreezeCAD`) и `<данные приложения>/logs/output.log`.
- Правки общего кода (только `#if __ANDROID__`): `Viewport` — часы анимации без GLFW,
  `InitEglContext` (без него OCCT отвергает чужой EGL-контекст), `Log` — logcat,
  `cmake/OpenCascade.cmake` — TKOpenGles. `BZ_BUILD_ANDROID_APP` (вкл. на Android).
- APK: `scripts/android/package-apk.sh` (aapt2/zipalign/apksigner, без Gradle;
  библиотеки по DT_NEEDED — 32 шт., ~23 МБ), иконка — из `assets/brand`,
  манифест — `resources/android/AndroidManifest.xml.in` (всегда альбомная,
  `io.github.mikeverx.breezecad`). versionCode = номер прогона CI.
- Подпись: секреты `ANDROID_KEYSTORE_BASE64` + `ANDROID_KEYSTORE_PASSWORD`
  (ключ сгенерирован 16.10.2026, хранится у автора). Без них — временный ключ,
  и старую версию перед установкой надо удалять.
- CI проверяет APK на эмуляторе: `scripts/android/smoke-apk.sh` — установка,
  запуск, деталь построена, свайп, процесс жив; снимки — в релиз.
- Проверено автором на OnePlus Nord CE5 (16.10.2026, сборка 10): установка,
  вращение, сдвиг двумя пальцами, щипок, двойное касание — работают.
  Подпись постоянным ключом подтверждена (отпечаток APK = ключ автора).
- Кэш OCCT виден только своей ветке (и веткам от `main`): новая ветка от `next`
  первый раз собирает OCCT заново (~1 ч). Если станет мешать — релиз `dev-deps`.

## Шаги 3–7: решения автора 16.10.2026 (ветка `feat/android-full`)

Автор попросил сделать шаги 3–7 одним заходом. Вопросы заданы одним списком в начале,
ответы:

| Тема | Решение |
|---|---|
| Где живут проекты | **Папка проектов**: один раз выбирается системным окном (SAF, дерево с постоянным доступом), дальше открытие/сохранение там без окна; «Открыть другой…» — системный выбор файла |
| Хотбар у выреза камеры | Сверху **лого**, под ним **«+»** — добавить инструмент в хотбар; внизу — **выбор цвета** (внешний вид). Между ними — добавленные пользователем |
| Нампад `a b c d` | **Буквы как есть** — это назначаемые переменные. Нужна кнопка **«предыдущий размер»** (подставляет последнее введённое значение) — будет использоваться часто |
| Google Play | CI собирает **AAB** рядом с APK; **политика конфиденциальности** (офлайн, без телеметрии) — в репо для GitHub Pages; targetSdk — по требованию Play. Без публикации |

Решения, принятые мной (технические, можно пересмотреть):

- На телефоне запускается тот же `Application`, что на десктопе. Окно и ввод — за
  `platform::Window` (GLFW на десктопе, EGL + `imgui_impl_android` на Android). На
  десктопе поведение не меняется.
- Вид выбирается по короткой стороне окна: **≥ 600 dp — планшет** (десктопная
  раскладка), меньше — мобильная. Ручной переключатель в настройках.
- Небольшая Java-часть (наследник `NativeActivity`): SAF, «Поделиться», клавиатура,
  immersive, вырез, сторож `:crash`, причины выхода. Сборка `javac` + `d8`, без Gradle.
- Нампад 7×4: `0–9 . ( ) + − × / a b c d ⌫ ↑ ↓ ⌨ ↵` + «пред.» (предыдущий размер).

## Шаги 3–7: как устроено (ветка `feat/android-full`, 16.10.2026)

**Программа целиком.** `libbreezecad.so` — это десктопный `Application` (просмотрщик шага 2
удалён). Вход — `src/app/android/AndroidMain.cpp` (`android_main`: распаковка ассетов, обработчики
сбоев, `Application`). Отличия от десктопа — только за `#if __ANDROID__` или в отдельных файлах
`*_android.cpp`; на десктопе поведение прежнее, кроме закреплённой «Принять эскиз» (ADR: во всех версиях).

| Где | Что |
|---|---|
| `platform/Window_android.cpp` | EGL на поверхности активности. Контекст живёт всё время, при уходе в фон пересоздаётся только поверхность; OCCT получает 1×1 pbuffer как «своё окно» (его вид рисует в свой framebuffer) |
| `platform/Android.{h,cpp}` | JNI-мост к `BreezeActivity`: вырез/панели/жесты/клавиатура (отступы в dp), SAF, «Поделиться», буфер обмена, причины выхода, состояние для сторожа |
| `platform/FileDialogs_android.cpp` | Открыть/сохранить: папка проектов без окна, иначе системный выбор; вызов ждёт ответа (как модальный диалог). Программа работает с локальной копией, `platform::FileWritten` копирует обратно |
| `app/Application_android.cpp` | Ввод, отступы, клавиатура (нампад для значений, системная — для имён и поиска), автосохранение при уходе в фон, проверка прошлого выхода, тестовые команды |
| `app/android/AndroidInput.cpp` | `AInputEvent` → указатели (палец/перо/ластик/мышь) и клавиши ImGui; «Назад» = Esc, на главной — системный; громкость — масштаб (настройка) |
| `app/mobile/Gestures.*` | Жесты таблицы ADR как чистая логика (тесты `tests/app/GestureTests.cpp`) |
| `app/mobile/TouchInput.*` | Куда идёт каждое касание: панели (тап, свайп-прокрутка, вбок — перетаскивание, зажатие = ПКМ) или вид (жесты → мышь для инструментов). Нампад — мимо ImGui, иначе поле теряет фокус |
| `app/mobile/Cursor.*` | Курсор-капля по макету (холст автора, доска «Sketch»): контур-капля, острие = кончик, круглый конец под пальцем на 48 dp ниже, пунктирное кольцо пальца, подсказка «тяни круг — кончик ведёт» в покое; лупа ×4 у кончика в эскизе. Курсор и лупа — в foreground-слое, кадр рисуется в два прохода (`RenderWithMagnifier`), иначе лупа увеличивала сам курсор |
| `app/mobile/MobileLayout.cpp` | Раскладка телефона: блоки 1–5, панель у выреза, кубик, полоса проектов, главная с папкой проектов, окно прошлого сбоя, меню «Поделиться» |
| `app/mobile/MobileRibbon.cpp` | Блок 2: то же содержимое, что лента (`RibbonSink`/`FillRibbon` в `shell/Ribbon.cpp`), списком |
| `app/mobile/Numpad.cpp` | Нампад 7×4 + «пред.» |
| `resources/android/java` | `BreezeActivity`, `Watchdog` (процесс `:crash`), `CrashActivity`, `ShareProvider`. Сборка `javac` + `d8` в `package-apk.sh` |

**Решения по ходу (мои, можно пересмотреть):**
- Вид — по короткой стороне окна: < 600 dp — телефон. Ручной выбор: «Управление → Сенсор».
- Масштаб интерфейса на телефоне не меньше 100 %: главные кнопки ≥ 44 dp ≈ 7 мм. Планшет по умолчанию 125 %.
- Кончик курсора — на 48 dp выше пальца (как на макете). Первый вызов курсора в 3D — по центру вида.
- Курсор вкл: зажатие = контекстное меню в точке кончика. ОК: тап — щелчок в кончике (с курсором)
  или «подтвердить» (без курсора); зажатие ОК — «подтвердить» всегда.
- Рамка — **одноразовая**: кнопка рамки включает её на одну рамку (с курсором: первый ОК — угол, второй — второй угол; без курсора — одно протягивание пальцем), потом снова вращение. Раньше режим оставался включённым — автор видел «вращение не работает».
- Блок 2: группы капителью; родственные команды (например, Сдвиг/По сечениям/Спираль под «Вращением», Фаска/Оболочка под «Скруглением») — одна строка с ˅, раскрывается тапом (таблица `kKin` в `MobileRibbon.cpp`). Иконки ленты в строках — одобрено автором.
- Большой кубик: под ним «Домой» и подсказка «1 палец — вращение», внизу вида — «тап вне кубика — свернуть».
- На телефоне в подвале операции — одна «Применить» во всю ширину (Отмена — кнопкой ряда блока 1, Готово — ОК). Окна (`BeginDialog`, «Новый документ») ужимаются по экрану.
- Состояние для сторожа и «пульс» пишет Java в `onCreate` до запуска сторожа — иначе он читал состояние прошлого запуска и показывал ложный экран BZ-UNKNOWN.
- Каждое касание пишет в лог строку `Touch: …` (куда ушло: панель/вид, кубик) — для отчётов с телефона и для проверки на эмуляторе.
- Блок 1: вкладки «Дерево / Инструмент / Размеры» (в сборке «Размеры» = свойства). Новый инструмент
  сам открывает вкладку «Инструмент». «Свойства детали» — через поиск/меню.
- Полоса проектов: тап — открыть, зажатие — закрыть (спросит о сохранении).
- Хотбар: «+» открывает список команд; зажатие кнопки хотбара убирает её.
- Нампад: «↵» запоминает значение для «пред.»; «пред.» выделяет текст поля и вписывает значение.
- Системные жесты у краёв не исключаются (решение автора: «не проблема»); проверить свайп наискось на телефоне.
- Сторож: уведомление при падении (процесс исчез в состоянии «fg») и при зависании (нет «пульса» 10 с в
  «fg»). Разрешение на уведомления спрашивается один раз через 3 с после старта.
- Срок отчёта для экрана ошибки — час; отчёт показывается в программе один раз (`reports/.shown`).
- Модули: не трогал. На Android папка модулей пуста, загружать нечего; запуск они не ломают.

**После второй проверки автором (запись 16.10, 20:11):**
- «Управление → Сенсор → Отзывчивость» (`MobileSettings`): вращение пальцем 50–200 %, порог касания (6/10/16/24 dp),
  долгое нажатие 0,3–1 с, скорость курсора 25–100 % (меньше 100 % — точный режим: кончик проходит часть пути пальца,
  тап по-прежнему ставит его в точку), кончик над пальцем 32–80 dp, прокрутка списков 50–200 %. Поиск команд находит
  «Настройки сенсора» по словам «чувствительность», «курсор», «касание» и т. п. (`Action::keywords`, только Android).
- Тап одним пальцем — всё, что отпущено до долгого нажатия и не сдвинулось дальше порога (было: короче 0,25 с — медленные
  нажатия терялись). Тап двумя-тремя пальцами (отмена/повтор) — по-прежнему быстрый (0,35 с).
- Списки докручиваются по инерции после свайпа (около секунды); новое касание останавливает.
- Системная клавиатура: Java держит настоящий буфер и шлёт в C++ разницу (как SDL), текст и клавиши идут одной очередью
  в порядке нажатия. Раньше буквы терялись и стирались не те.
- Подсказки сверху вида (`viewport/ViewPrompt.h`) на телефоне — под островками и с переносом строк; без «(S)» и «ленты».
- Сочетания клавиш (Ctrl+N, Esc…) на кнопках и в меню скрыты, пока нет аппаратной клавиатуры (`ui::Ui::keyHints`).
- Нампад: «↵» — значком (в шрифте нет символа); «пред.» запоминается при любом выходе из поля, не только по «↵»; на низком
  экране нампад закрывает блок целиком, содержимое не просвечивает.
- Заголовки панелей и вкладки обрезаются с «…», подписи сегментов сжимаются под ширину.
- Конфликт ID «##cube-home» (окно Dear ImGui на большом кубе) исправлен.

**Телефонная раскладка на десктопе** (проверка на Xvfb без эмулятора): `BZ_PHONE_LAYOUT=1`, окно 915×412 (`UI_SIZE="915 412" scripts/ui-test/ui.sh start …`). На десктопе без переменной не включается.

**Тестовые команды** (только CI): `adb shell am start -n io.github.mikeverx.breezecad/.BreezeActivity
--es bz "example,sketch,line"`. Список — `Application::RunTestCommands`.

**Сборка в песочнице Claude:** `bash scripts/android/dev-setup.sh` (NDK, OCCT под Android и SDK из
пре-релиза `android-dev-deps`; выкладывается workflow `android-dev-deps`, запуск — правка
`.github/android-dev-deps.stamp`), затем пресет `android-x86_64`.

## Google Play (подготовлено, не опубликовано)

- CI собирает `BreezeCAD-android.aab` (arm64, bundletool, подпись тем же ключом — в Play он станет
  ключом загрузки, Play App Signing). Лежит в `android-build` рядом с APK.
- targetSdk — новейшая выпущенная платформа на раннере (требование Play — не ниже актуального уровня).
- Иконка: адаптивная (`mipmap-anydpi-v26`), для карточки — `resources/android/play/icon-512.png`.
  Нужна ещё картинка 1024×500 и скриншоты — снимки эмулятора из `android-build` подходят как черновик.
- Политика конфиденциальности — `docs/privacy.html`. Ссылка в «О программе» ведёт на
  https://mikeverx.github.io/breezecad/privacy.html — **автору включить GitHub Pages** (ветка main, папка /docs).
- Анкета Data safety: данные не собираются и не передаются. Разрешение одно — уведомления.
- Модули: в сборке для Play нативные модули скачивать нельзя (ADR-0005) — до публикации нужен флаг сборки
  «для магазина», который прячет установку `.bzmod` с нативным кодом.

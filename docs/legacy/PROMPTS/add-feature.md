# Промт: Добавление фичи

**Когда использовать:** когда добавляем новую функцию (операцию, панель,
диалог). Копируется как задача для ассистента.

---

## Текст промта

Задача: **добавить фичу [НАЗВАНИЕ].**

### Обязательные шаги

**Шаг 1. Сверить с каноном.**
- Открыть `docs/CANON_FEATURES.md`.
- Найти эту фичу. Если нет — обсудить с MikeVerx до начала работы.
- Проверить `docs/BUTTONS_INVENTORY.md` — статус (❌ / ⚠️ / ✅).

**Шаг 2. Определить место.**
- В какой вкладке? В какой группе?
- Какой размер кнопки (большая / средняя / малая)?
- Нужна ли выпадашка ▼?

**Шаг 3. Продумать архитектуру.**
- UI-часть: где отрисовывается (файл, функция).
- Логика: где живёт (app / doc / kernel).
- Данные: что хранится в документе.
- Если операция — есть ли запись в `history.bin` (OperationRecord)?

**Шаг 4. План.**
Написать пользователю план:
- Что делаем.
- Какие файлы трогаем.
- Как проверяем.
- Риски.

**Шаг 5. Реализация.**
- Один коммит на логическую часть.
- После каждого — сборка + запуск + проверка.
- При падении — откат, не докручивание.

**Шаг 6. Проверка.**
- Сборка чистая.
- Функция работает (скрин / тест).
- Ничего не сломано рядом.

**Шаг 7. Документация.**
- Обновить `BUTTONS_INVENTORY.md` (статус ⚠️ → ✅).
- Обновить `CHANGELOG_WORK.md`.
- Если архитектурное — ADR.
- Если новая проблема — TECH_DEBT или UI_ISSUES.

### Критерий готовности

- Функция в каноне.
- Работает и проверена.
- Статус обновлён.
- Коммит с понятным сообщением.

---

## Пример: добавление «Отверстие»

**Канон:** группа «Изменить» в 3D-модели, большая кнопка, есть в
CANON_FEATURES.

**Архитектура:**
- UI: `ui/dialogs/HoleDialog.cpp` — плавающее окно.
- Логика: `kernel/OcctKernel::makeHole(...)`.
- Данные: `OperationRecord` с типом `HOLE`.
- Кэш: B-rep тела после операции.

**План:**
1. Создать `HoleDialog` — окно с полями (тип, диаметр, глубина, резьба).
2. Добавить `makeHole` в IKernel.
3. Связать в Application: клик → открыть диалог → вызвать ядро.
4. Сохранить операцию в history.
5. Обновить preview.
6. Тесты: проверка через STEP-экспорт.

**Коммиты:**
- `feat(kernel): add Hole operation to IKernel`
- `feat(ui): add Hole dialog`
- `feat(app): wire Hole dialog to kernel`
- `docs: update buttons inventory and changelog`

## Общие правила

### Что всегда

- Сверка с CANON_FEATURES.
- План перед патчем.
- Один коммит на логическую часть.
- Сборка после каждого шага.
- Обновление документации.

### Что никогда

- Не добавлять фичу, которой нет в каноне.
- Не трогать layout ribbon без сверки с UI_LAYOUT / CANON.
- Не менять формат `.bzc` без ADR и миграции.
- Не блокировать UI долгими операциями — только в фоне.
- Не хардкодить пути.

### Если фича большая

Разбить на подзадачи:
1. Минимальная работающая версия (MVP фичи).
2. UI-доработка.
3. Оптимизация.
4. Тесты.

Каждая подзадача — отдельный коммит.

## Вопросы, которые задать до начала

1. Есть ли фича в `CANON_FEATURES.md`?
2. В какой вкладке и группе?
3. Какой размер кнопки?
4. Нужны ли данные в `.bzc`?
5. Влияет ли на другие фичи?
6. Что проверяем после?

Если на все 6 есть ответ — можно начинать.

---

## Что делать после

1. Обновить `BUTTONS_INVENTORY.md`.
2. Обновить `CHANGELOG_WORK.md`.
3. Если фича изменила UI — обновить `UI_LAYOUT.md`.
4. Если архитектура — ADR.
5. Скрин в чат (для истории).

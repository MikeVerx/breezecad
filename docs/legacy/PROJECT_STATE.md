## Что за проект

BreezeCAD — кросс-платформенный САПР. Цель: полноценное параметрическое
моделирование (эскиз → операция → сборка) уровня Autodesk Inventor / КОМПАС-3D,
но существенно легче и быстрее.

**Целевые платформы:**
- Windows (включая слабые ПК: 4 ГБ ОЗУ, слабый iGPU)
- macOS (Intel + Apple Silicon)
- Android (планшет + клавиатура + мышь как основной сценарий)
- ARM везде, где возможно

**Целевой вес:** 200–500 МБ установленной сборки.
**Целевой старт:** < 1 сек на среднем железе.

## Что удалено / не делаем

Зафиксировано в ADR-0001. Кратко:

- FEA/CFD, CAM, BIM, анимация (общая), полигональное моделирование
- Обратный инжиниринг (mesh → solid), generative design, топологическая оптимизация
- Синхронное моделирование (ST-style), облако/коллаборация/PLM
- IGES (устарел), импорт родных форматов (.ipt, .sldprt, .m3d)
- ECAD-интеграция

Отдельные модули (не в ядре):
- Сборки, стандартные изделия, чертежи, рендеринг (+ анимации),
  листовой металл, сварка/трубопроводы/кабели

Отложено: параметрические таблицы, конфигурации, iLogic-правила,
динамика движения сборок.

## Соглашения

### Работа с пользователем (MikeVerx)

- **ТОЛЬКО консольные команды.** Никаких «открой редактор и найди строку».
- Любая правка файла = одна команда в терминале (`python`, `sed`, `cat << EOF`).
- После каждой правки — команда **проверки** (`grep`, `diff`, `head`).
- Всегда добавлять **команды запуска приложения** для проверки.
- **Никогда не просить ребут** — искать решение без перезагрузки системы.
- Пользователь не обязан разбираться в C++/Linux — объяснять простыми словами.

### Инструменты

- **Правки файлов:** Python с `newline=''` (сохраняет CRLF). Не `sed -i` — ломает line endings.
- **Поиск в UTF-8 файлах:** `grep -a`. Иначе «Binary file matches».
- **Кириллица в bash:** избегать в `python -c "..."`. Использовать `python << 'PYEOF'` heredoc.
- **Assembly-вывод:** `LC_ALL=C objdump | tr -d '\0' | grep -aE 'DLL Name:' | awk '{print $3}'`.
- **Сборка:** `ninja` в `~/BreezeCAD/build`.
- **Запуск:** `~/BreezeCAD/run.sh`.
- **Договорённость:** правки в файлах всегда через консоль, не через редактор.

### Отладка

- **TRACE-инструментация.** В `Application::Run()` вставлены вызовы
  `TRACE("iter: ...")`. По умолчанию они **ничего не делают** — no-op,
  никакого оверхеда.
- **Включение:** `BREEZECAD_TRACE=1 ./breezecad.exe`. Тогда пишется
  файл `breezecad_trace.log` рядом с exe, с fflush после каждой строки.
- **Когда использовать:** когда приложение ведёт себя странно (белый
  экран, зависание, обрыв). Trace покажет точную точку обрыва.
- **Не оставлять `BREEZECAD_TRACE=1` в постоянной работе** — на слабом
  железе запись в файл каждый кадр может тормозить.

### Git-workflow

- После каждой рабочей сессии — коммит + push.
- Формат сообщения:
Типы: `feat`, `fix`, `refactor`, `docs`, `build`, `chore`.
- Ветки: `main` — стабильное состояние. Эксперименты — в feature-ветках.
- Теги для значимых вех: `git tag -a v0.X.Y -m "..."`.

### Кроссплатформенность

- Хардкод путей запрещён. Только `std::filesystem` или `glfw`-хелперы.
- `FileDialog` сейчас только Win32 — при выходе на Linux/Mac/Android нужны реализации.
- `#ifdef _WIN32` — только там, где действительно платформенно-специфично.

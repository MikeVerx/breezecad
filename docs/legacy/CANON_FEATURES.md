# BreezeCAD — Канон функционала

**Единый источник правды о том, что должно быть в программе.**
Любая сверка кода идёт по этому файлу. Если функции нет здесь — она лишняя.
Если функция есть здесь, а в коде нет — её надо добавить.

**Дата утверждения:** 2026-09-23
**Статус:** активный канон

## 1. Манифест проекта

### Философия

**Уважение ко времени пользователя.** Пусть лучше частые автосохранения,
но они позволяют вернуться к работе после краша за 5 секунд.

**Ноль телеметрии.** Никаких «отправить отчёт в Microsoft». Всё локально.

**Языки.** Сейчас — русский (для скорости разработки). Языковые пакеты
расширим после MVP. Архитектура локализации готова.

**Код — приятный для чужого программиста.** Опытный C++-разработчик должен
понять проект за 5 минут и не поморщиться.

### Целевое железо

- **Минимум:** Intel Core i3-4170 (или аналог AMD), 8 ГБ DDR3, iGPU,
  HDD/SATA SSD.
- **Комфорт:** Ryzen 5 5800H + Vega 8, 32 ГБ DDR4, NVMe SSD.
- **Планшеты:** средний ARM (Snapdragon 7xx), Android.
- **Mac:** Apple Silicon (M1 и новее).
- **Тест-девайс:** GWNR51416-BL (Ryzen 5 + Vega 8).

### Целевой вес и старт

- **Вес:** 200–500 МБ (желательно <300 МБ).
- **Старт:** <1 сек на среднем железе.
- **Открытие детали (100 фич):** <2 сек.
- **Открытие сборки (200 деталей):** RAM ≤500 МБ.

- Таблица: `d0 = 10`, `d1 = 20`, `d2 = d0 * 2`

**Правила:**
- Управление шириной — splitter.
- Управление высотой — вертикальный скролл (колесо + ползунок).

## 9. Workspaces (режимы работы)

| Workspace | Открывается | Ribbon |
|---|---|---|
| **Деталь** | `.bzc` (деталь) | 3D-модель / Эскиз / Вид |
| **Сборка** | `.bzc` (сборка) | Сборка / 3D-модель / Эскиз / Вид |
| **Черчение** | `.bzc` (чертёж) — модуль | Черчение / Вид |
| **Эскиз** (подрежим) | внутри Детали/Сборки | Эскиз |
| **STL Viewer** | `.stl` | Просмотр / Измерение |

### STL Viewer — отдельный workspace

**Назначение:** открыть скачанный STL, извлечь размеры, не редактируя.
Никакой реверс-инжиниринг, никаких операций.

**Модуль по умолчанию:** только **Измерения**.
- Расстояние между точками
- Расстояние между плоскостями
- Угол между гранями
- Диаметр цилиндрических поверхностей
- МЦХ (объём, центр тяжести)

**Что нельзя:**
- Редактировать геометрию
- Строить поверх
- Конвертировать в деталь

Если пользователю нужен реверс-инжиниринг — идёт в Geomagic X.
Мы такое не делаем.

## 10. Автосохранения (в MVP, по умолчанию включено)

**Механика:**

- Каждую минуту (настраивается).
- Если есть изменения.
- В фоновом потоке (`std::async`) — не блокирует UI.

**3 версии + atomic write:**

[раз в минуту] → .autosave_1
[через минуту] → .autosave_1 → .autosave_2, новый в .autosave_1
[через минуту] → .autosave_2 → .autosave_3, новый в .autosave_1
[через минуту] → .autosave_3 удаляем, сдвиг вниз, новый в .autosave_1

**Atomic write:** пишем в `.autosave_1.tmp`, потом `rename()` в `.autosave_1`.
Rename — атомарная операция. Даже если комп выключился — файл целый.

**При старте после краша:**
⚠ Обнаружено некорректное завершение работы.
Последние автосохранения:

● 14:32:05 (2 минуты назад) ← восстановить
○ 14:31:05 (3 минуты назад)
○ 14:30:05 (4 минуты назад)

[Восстановить выбранное] [Открыть оригинал] [Игнорировать]

## 11. Модульная архитектура

### Что в базе

- Деталь (эскиз, операции, дерево, диагностика)
- Сборка (компоненты, зависимости, соединения, BOM)
- Стандартные изделия
- STL Viewer (только измерения)
- Автосохранения

### Что модульно (подключается отдельно)

| Модуль | Вес | Требования |
|---|---|---|
| **Черчение** | ~60 МБ | Среднее железо |
| **OCAF-мост** (для `.cbf`) | ~5 МБ | Совместимость |
| **Рендер + анимации** | ~80 МБ | GPU с 4 ГБ VRAM |
| **Трассировка лучей** | ~30 МБ | GPU с RT-ядрами |
| **FEA/CFD** | Не делаем | — |
| **CAM** | Не делаем | — |

**Правило:** при установке модуля проверяем железо. Не проходит — кнопка
«Установить» неактивна с тултипом, чего не хватает.

### Плагинная система (Фаза 5+)

**Триггер:** ядро стабильно, формат `.bzc` работает, есть 3–5 модулей от нас.

**Что даёт:**
- UI-темы (JSON) — ноль кода.
- Скрипты (Lua) — лёгкий интерпретатор.
- C++ плагины (C-ABI) — для тяжёлых модулей.

**Защита от крашей:**
- Отдельный процесс-менеджер для отключения крашащих плагинов.
- Диалог при краше: скопировать отчёт, отключить плагин, восстановить.

**Влияние на производительность:** близко к 0 (плагины вызываются
только когда пользователь активирует).

## 12. Формат файлов

**Полное описание:** `docs/FILE_FORMAT.md`.

**TL;DR:** формат `.bzc` — ZIP-контейнер.
- `manifest.json` — версия формата, программы, OCCT
- `history.bin` — параметрическая история
- `geometry.brep` — кэш B-rep
- `tessellation.bin` — кэш триангуляции
- `parameters.json` — переменные
- `materials.json` — материалы

**Миграции между версиями обязательны.** Не удаляем старые.

**OCAF** — только как модуль-мост для `.cbf`.

**Кэширование промежуточных состояний** — с момента создания `.bzc`.

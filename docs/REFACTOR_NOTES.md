## D. Заметки по процессу

### D-01. Mixed line endings
В `Application.cpp` и `Application.h` **смешанные переводы строк**: часть строк CRLF, часть LF. Появлялись из-за патчей, которые вставляли `\n` вместо `\r\n`.

**Решение:** при написании патчей использовать **построчную обработку** с `rstrip('\r')` и явным контролем переводов. Характерный поиск (character-level) с brace-counting для функций.

### D-02. Слипшиеся комментарии в include
При вставке нового include с якорем, включающим хвостовой комментарий, получается слипшаяся строка вида:
#include "a.h" // comment1 // comment2
**Решение:** якорь = только `#include "..."` без комментария. Проверять после каждого патча через `sed -n 'N,Mp'`.

### D-03. Brace-counting работает, но...
Иногда мои скрипты вырезают **только первый if-блок** из цепочки, оставляя осиротевшие следующие. Пример: `if (a) { ... }` + `if (b) { ... }` — если вырезать первый, второй продолжает открывать popup вхолостую.

**Решение:** после вырезания блока — проверять, не остался ли характерный фрагмент второго блока (`BeginPopupModal`, `EndChild` и т.п.).

### D-04. Расширение `Application.h` — риск срыва сигнатур
При замене сигнатуры лямбды-коллбека (`onNotImplemented()` → `onNotImplemented(const char*)`) есть места в коде, где функция вызывается без аргумента — компилятор их не подсвечивает в отрыве.

**Решение:** после смены сигнатуры — `grep` по **всем** местам вызова, не только тем, что помнишь.

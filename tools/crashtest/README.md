# Краш-тест BreezeCAD

Проверка устойчивости сборки программы на виртуальном экране (Linux, Xvfb):

| Скрипт | Что делает |
|---|---|
| `samples.py` | делает образцы самой программой: плита + крышка, спроектированная в сборке (адаптивная проекция), и редуктор с передачей |
| `recovery.py` | предохранитель (`app/Recovery.h`): изменение + сбой (SIGSEGV / исключение) в команде, в отложенной работе и посреди отрисовки интерфейса — программа жива, документ ровно как до сбоя |
| `fuzz.py SEED STEPS` | случайные цепочки команд сборки, правки на месте, деталей, отмены, сохранения |
| `filefuzz.py SEED COUNT` | повреждённые сборки и детали (обрезанные, не JSON, не те типы, NaN/1e300, дубли id) — открыть и поработать |
| `monkey.py SEED ACTIONS` | случайные щелчки, двойные щелчки, перетаскивания и клавиши по всему окну |
| `run.sh [BIN] [STEPS]` | всё по очереди; итог — число срабатываний предохранителя и сообщений санитайзера |

```bash
cmake --build --preset linux-debug && tools/crashtest/run.sh
cmake --preset linux-asan && cmake --build --preset linux-asan && tools/crashtest/run.sh build/linux-asan/bin
```

Нужны Xvfb, xdotool, python3 и модуль mcp (команды идут через него). Строка
`Recovered:` в журнале программы — сбой, который поймал предохранитель:
программа не упала, но это ошибка, её надо исправить. Журналы шагов —
в `$BZ_CRASHTEST` (по умолчанию `/tmp/bz-crashtest`): по ним сбой повторяется.
